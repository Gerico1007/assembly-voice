>   and multiplexer target. Landed 2026-08-09 (PRs #13 #14 #15 #16 #17, all merged).

>   copyable jump commands (ssh with bash -lc, and a local one guarded on $HERDR_ENV).

## Ambiguity Flags

- **"'Look at all what you have access to' — the scope of 'all' is unbounded: MCP servers, skills, hooks, runtimes, mesh nodes"**
  - Suggestion: Fix an explicit inventory boundary — e.g. skills directories, agent runtime command dirs, herdr/tmux surfaces, and the assembly-voice repo — and state what was excluded
- **"'Would it be easy to have a box' — 'box' could mean a checkbox, a button, a modal dialog, or a copyable text field like the existing jump commands"**
  - Suggestion: Confirm whether close follows the copy-command pattern already on the card (safest, human executes) or actually executes remotely from the portal
- **"Whether the close button executes the close itself or only generates the command — Jerry says both 'it will generate the command' and 'I just click and it will close the session'"**
  - Suggestion: Resolve explicitly: generate-and-copy is non-destructive and matches existing jump commands; execute-on-click needs a real confirmation and an execution channel
- **"Which close granularity the button targets: pane, tab, workspace, or tmux session — Jerry says both 'close the pane' and 'close the session'"**
  - Suggestion: Scope the issue to pane-level close first, and note tab/workspace/session as follow-ups
- **"'A slash command for Hermes, for Claude, for Codex' — unclear whether all three ship now or one is a reference implementation"**
  - Suggestion: Pick Claude Code as reference implementation, then port; state which are shipping in this pass
- **"'Go further, in which direction' leaves the axis unspecified — reach, autonomy, fidelity, and archive are all plausible"**
  - Suggestion: Propose a small ranked set of directions with the no-regression constraint attached to each, and mark the recommended one
- **"'More autonomous — taking that decision by yourself' does not say which decisions may be taken without asking"**
  - Suggestion: State the autonomy boundary explicitly: authoring skills/docs/issues without asking, but no destructive or outward-facing action without consent
- **"Whether the 407 legacy records should be backfilled with origin, left as 'no address', or archived"**
  - Suggestion: Ask whether legacy backfill is in scope for the next version or permanently out
